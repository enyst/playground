# F28 — Instance skins

A skin is one Git-backed instance package: it restores configuration and runs a custom web app inside Canvas at `/skin`. Settings → Skin (`/settings/skin`) installs and manages it. Canvas apps (F20) remain independent sidebar pages. An explicit home pin takes priority, and `/conversations` keeps the built-in home reachable.

Source: `src/routes/skin-settings.tsx`, `src/routes/skin-tab.tsx`, `src/routes/index-home.tsx`, `src/api/skin-service.ts`, `src/hooks/query/use-skin.ts`, `src/hooks/use-skin-theme.ts`, `src/components/features/sidebar/sidebar-rail-body.tsx`, `src/constants/settings-nav.tsx`, `scripts/skin-service.mjs`, `scripts/skin-configuration.mjs`, `scripts/skin-export-safety.mjs`, `scripts/static-server.mjs`, `scripts/skin-runtime.mjs`, `docker/entrypoint.sh`, `src/fixtures/skins/demo-skin/`.

## Sub-features

- `F28.entry-points`: Settings → Skin and the direct settings URL open the same screen.
- `F28.install-form`: a supported owning backend shows repository URL/local path, optional ref and Install; whitespace disables Install and auto-push starts off.
- `F28.empty-tab`: `/skin` without an installed skin explains that none is installed; there is no iframe.
- `F28.install`: a reviewed GitHub repository or absolute local Git repository installs its app and configuration; unsupported sources and failed installs show their reason.
- `F28.skin-home`: an installed skin gets the topmost rail entry; `/` opens its `/skin-app/` iframe unless a home pin exists, and its local API works.
- `F28.home-pin`: an explicit home pin wins over the installed skin; unpinning restores the skin default.
- `F28.backend-ownership`: only the local backend hosting this Canvas origin can manage or apply its skin; switching to another backend removes its rail entry, iframe and theme.
- `F28.secret-setup`: declared names and missing configuration dependencies produce masked inputs; Save stores backend secrets and retries configuration apply.
- `F28.auto-push`: the installed setting persists; configuration export honors it while source/archive review requirements prevent an automatic push.
- `F28.pull`: pulling fast-forwards the checkout, reapplies configuration and restarts the app, reporting partial results and failures.
- `F28.push`: pushing uses the saved Git identity and reports actual success, required source review or failure; known credentials cannot be overridden by review.
- `F28.export`: export writes a portable configuration kit with secret references and names, never source values; archives and freeform code remain subject to review.
- `F28.uninstall`: confirmation precedes removal of the app checkout and synced skill; the install form, unskinned home and ordinary theme return.
- `F28.theme`: validated colors apply to Canvas and the embedded app, and disappear when the owning backend is left or the skin is uninstalled.
- `F28.phone`: the settings and installed iframe fit at 390×844.
- `F28.restart`: run-owned checkout edits become visible after the UI Restart action; a stack restart preserves installation and its port allocation.
- `F28.restore`: an exported kit restores supported configuration on a fresh backend, remapping IDs, resolving package-relative skills, requesting destination secrets and keeping automations inactive.

## How to get to it (user POV)

- Sidebar settings gear → **Skin**, or `/settings/skin` directly.
- The installed skin's named top sidebar entry (`sidebar-skin-link`), or `/skin` directly.
- `/` uses the pinned page first, then the installed skin, then the built-in home. `/conversations` always reaches the built-in home.
- Apps stay under Customize → Apps (`/apps`, F20); enabled app entries coexist with the skin.

## Driving it with control-openhands

Preconditions:

- Start an isolated supported stack with `control-openhands launch --new --skin --print-run`, set `$OH_VERIFY_RUN` to the printed directory, then run `control-openhands doctor` and `control-openhands onboard --skip`. No LLM call is needed. The fixture stores an offline loopback provider configuration; do not start a conversation or enable its automation.
- `--skin` reserves a free app port and private skin state/checkout paths. Without it the ordinary local stack shows the explicit unsupported-service message; Cloud and other backend origins show the ownership restriction. Docker supplies the corresponding static-server skin flags.
- Create a local remote with `control-openhands fixture git-remote --name qa-skin-remote`, then `control-openhands fixture git-repo --name qa-skin-source --remote "$OH_VERIFY_RUN/workspace/qa-skin-remote.git"`. Copy the reviewed fixture with `cp -a src/fixtures/skins/demo-skin/. "$OH_VERIFY_RUN/workspace/qa-skin-source/"`.
- In that disposable manifest, seed `app_preferences.git_user_name` as `QA Fixture` and `git_user_email` as `qa@example.invalid`. Commit the copied source with `git -C "$OH_VERIFY_RUN/workspace/qa-skin-source" -c user.name='QA Fixture' -c user.email=qa@example.invalid commit -am 'Add reviewed local skin fixture'` after adding its new files, then push its main branch to the run-owned bare remote. Do not patch the installed checkout's Git identity to conceal a product failure.
- Put disposable token/provider values in run-private files `qa-token` and `qa-provider-key` for `browser fill --value-file`. They are destination credentials, not fixture content. All Git writes in this recipe target the run-owned local bare repository; it authorizes no external repository write.
- For restore, launch a second fresh `--skin` run with its own browser and key files, set `$RESTORE_RUN` to its directory and doctor/onboard it. Keep the source run available until export/push and the ownership-switch check finish. Address both runs explicitly.

## Gotchas

- The 2026-10-14 scoped local-fixture lifecycle exercised all 17 F28 groups, including a genuinely fresh destination install. The [reviewed verification record](../../../../../.pr/16232/EVIDENCE.md) distinguishes frontend build identity, reloaded manager revision, persisted backend assertions and historical failed attempts. This is not a full feature-map baseline pass.
- The Canvas route is `/skin`; the custom app and its API are under `/skin-app/`. A configured Canvas base path (such as Docker `/canvas`) prefixes Canvas routes, never the app/management prefixes.
- Skins run reviewed repository code with instance backend access. The fixture uses no external dependencies, models or repository writes. Its disabled automation and offline provider metadata are configuration proof, not model or automation-execution proof.
- Ownership requires a local backend on the Canvas origin; equivalent loopback names need the same protocol and port. Another healthy localhost port does not own this instance.
- Status is keyed by backend and connection revision, and installed skins refresh every five seconds. Mutation invalidation and readiness polling drive updates; wait for visible end states instead of assuming a toast proves them.
- Operations share a lock. Pending install/apply/export/pull/push/restart/uninstall disables competing controls. Auto-push defaults off; known credential findings reject manual pushes even after review.
- Automation 1.19.3 forbids supplying both `model` and `agent_profile_id`. The 2026-10-14 live fixture exposed that restore defect; the fix omits model when the restored agent UUID owns the LLM choice. An empty 204 upload-cleanup response also needs no JSON parsing. Retain failed first-attempt evidence separately from the fixed rerun.
- SDK 1.54 seeds an untouched `default` agent before its `default` LLM exists. Export explicitly omits only that exact unused, unmodified seed when its LLM is absent. Other unresolved active, automation or customized profile dependencies fail export and preserve the previous kit; the exporter never infers an unrelated model binding.
- Uninstall removes the skin files and synced skill but deliberately keeps previously imported backend configuration. Cleanup checks must not mistake that retained configuration for an installed skin.
- A launcher left as a PID-1-owned zombie can make the current CLI stop report false despite closed ports. Inspect only the owned group and verify sockets; never signal other sessions by process-name patterns.
